# Price Is Not Revenue: the 9.4x Question

[![reproduce](https://github.com/bennytimz/price-is-not-revenue/actions/workflows/reproduce.yml/badge.svg)](https://github.com/bennytimz/price-is-not-revenue/actions/workflows/reproduce.yml)

> **My call:** NEAR's protocol revenue, mostly retained Intents revenue (about $20M a year), covers about 15% of the value of new token supply; I would not value NEAR on cash flow until revenue approaches about $191M a year (9.4x), and the dated thresholds in THESIS.md and PREDICTIONS.md say when I would change my mind.

## Summary for judges

**Claim:** NEAR is an option on NEAR Intents revenue, not yet a cash-flow story: the revenue is real but would need to grow about 9.4 times before buybacks offset new token supply.

**Test labels:**
- **H1 to H5:** confirmatory tests, written down before the long history was analysed.
- **E1 to E5 and F1 to F2:** public-source cross-checks, committed to git (Amendments 8 and 9) before their data was pulled.
- **X1 to X8:** exploratory checks, not pre-registered.

"Amendment" refers to a dated entry in `PREREGISTRATION.md`.

- **Revenue is now Intents:** retained Intents revenue was 92% of NEAR's protocol revenue in October 2026, and an independent DefiLlama pull totals 0.998 of Blockworks' figure (X1).
- **Dilution dwarfs revenue:** new supply is worth $137M a year at $4.28, against $20.3M a year of trailing-91-day revenue. Buybacks offset it only at 9.4 times that run-rate ($191M a year).
- **Valuation depends on the definition:** NEAR is 276 times sales on total revenue (peer median 647x) but 3928 times on gas fees alone.
- **The Sep-Oct revenue jump was only partly volume (E2: mixed):** volume rose 1.627 times, revenue 3.204 times, because the take rate went from 2.61 to 5.13 basis points.
- **Tests that failed:**
  - E3: Intents volume did not lead on-chain usage better than price (+0.178 against +0.336), so it is not supported.
  - E5: Blockworks active addresses and on-chain signers are inconsistent (0.479 against a 0.60 bar).
  - H2: activity led price in the fit period but failed out of sample (R-squared -76.2%).
- **A data-definition break:** on 2026-04-02 Blockworks active addresses fell 89.4% while on-chain signers fell 8.1%, so the drop is probably a Blockworks definition change (E4).

A pre-registered, reproducible test of whether NEAR Intents can carry NEAR's valuation. NEAR is an option on Intents revenue, not yet a cash-flow story.

Submission for the NEAR Hackathon, Investment Thesis track. Built by Benny (GitHub: Bennytimz) with AI assistance. Research only, not investment advice.

## Gross Intents fees vs retained revenue to NEAR

These are different numbers:
- **Gross Intents fees** are everything charged on NEAR Intents swaps: NEAR's protocol fee plus the affiliate (distribution) fees that front-ends collect, as DefiLlama defines them.
- **Retained revenue to NEAR** is the part that ends up in NEAR-owned revenue wallets. Blockworks calls it retained Intents revenue, and it is the figure used throughout.

Over the 91 days to 2026-11-01, gross fees annualised to $70.5M a year and retained revenue to $18.9M, which is 26.8% of gross (exploratory X5 in `extension_results.txt`). Every P/S figure and the 9.4x break-even use protocol revenue (gas fees plus retained revenue), never gross fees.

```
VERDICT E1: usable proxy
```

This runs `verify_data.py`, `analysis_confirmatory.py`, `scenarios.py`, `analysis_extension.py` and `build_dashboard.py`, rewrites `confirmatory_results.txt`, `scenarios_results.txt`, `extension_results.txt` and `dashboard.html` (plus the three `*_numbers.json` files). It reads only from this folder, with one exception: if the local DefiLlama files are missing (they are not in the repository, see Data terms), it first pulls them from DefiLlama's free API, which needs an internet connection but no key. The source for the data is Blockworks, which needs an API key to re-pull, so the committed CSVs are the reproducible input. Each dashboard chart names the code and data file behind it.

On Windows, Python may write CRLF line endings; the outputs are byte-identical to the committed ones after normalising to LF (tested: all seven output files match).

**Re-pulling the BigQuery series (optional, not needed for `run_all.py`).** `pull_bigquery.py` runs the two committed queries (`pull_bigquery_daily_usage.sql` and `pull_bigquery_intents_contract.sql`) against NEAR's public BigQuery dataset, with the end date capped at 2026-11-04 so the result is comparable with the committed pulls.
- Setup: `pip install -r requirements-bigquery.txt`, Google application-default credentials (for example `gcloud auth application-default login`, which opens a browser), and a project in the `GCP_PROJECT` environment variable or in `gcloud config`. No credentials are stored in this repository.
- `python pull_bigquery.py` is a dry run: it prints the bytes each query would process and runs nothing. It refuses to go further if either query exceeds `--max-gb` (default 150).
- `python pull_bigquery.py --run` executes both queries (BigQuery bills the processed bytes to your project) and writes `repull_bigquery_daily_usage.csv` and `repull_bigquery_intents_contract.csv`, which git ignores. It never overwrites the committed `raw_*.csv` files. It then compares them with the committed pulls for days up to 2026-11-04 (row counts, column sums, first and last dates, and any days that differ) and prints MATCH or DIFFER. Days the committed pulls have after 2026-11-04 are left out of the comparison.
- Checked on 2026-11-12: the dry run measured 132.3 GB for `pull_bigquery_daily_usage.sql` and 125.9 GB for `pull_bigquery_intents_contract.sql` (both with the 2026-11-04 cap). `--run` gave **MATCH** for both: 1,039 and 673 rows, the same first and last dates, the same column sums, and no day that differs from the committed pulls.

### Public sources and how to re-pull them

| Source | What | Raw file | How to re-pull |
|---|---|---|---|
| S1, DefiLlama free API (no key) | NEAR Intents daily volume, fees and revenue | Not in the repository; pulled into local `raw_defillama_intents*.json` files that git ignores | Automatic: `run_all.py` pulls them if missing. Manual: `python pull_defillama_intents.py` (add `--force` to replace local copies). Endpoints `api.llama.fi/summary/dexs/near-intents` and `api.llama.fi/summary/fees/near-intents` |
| S2, NEAR public BigQuery dataset | Daily transactions and distinct `signer_account_id` | `raw_bigquery_daily_usage.csv` | Run `pull_bigquery_daily_usage.sql` in the BigQuery web console and download the result as CSV (see below) |
| S4, NEAR public BigQuery dataset (Amendment 9) | Daily calls to the Intents settlement contract `intents.near` and their distinct signers; tests F1 and F2 | `raw_bigquery_intents_contract.csv` | Run `pull_bigquery_intents_contract.sql` in the BigQuery web console and download the result as CSV |
| S3, Intents Explorer API | Sampled swaps | none | Not run |

The BigQuery query (it processed 123 GB when run on 2026-11-11; the `block_date` filter matters because the table is partitioned on it, and without it the query scans the whole table):

```sql
SELECT block_date, COUNT(*) AS transactions, COUNT(DISTINCT signer_account_id) AS active_signers
FROM `bigquery-public-data.crypto_near_mainnet_us.transactions`
WHERE block_date >= '2024-01-01'
GROUP BY block_date ORDER BY block_date
```

The tests use fixed date windows, so later days in a re-pull do not change them. A source can still revise history:
- **BigQuery:** a re-pull's hash will not match `RAW_PULLS.sha256`. The committed CSV is what the results were computed from.
- **DefiLlama:** `verify_data.py` checks that the pull covers the test dates, and `verify_data.py --extension` compares E1 to E3, X1 and X5 with the published values within the tolerances in `extension_expected.json`. It warns, rather than fails, if they differ.

## Where the data came from and how it was checked

The baseline series come from Blockworks, pulled through the Blockworks MCP in ChatGPT; the CSV files here are rebuilt from the raw exports by `build_clean_data.py`. The exact prompts, and the row count and sum check for each raw file, are in [DATA_PROVENANCE.md](DATA_PROVENANCE.md). The public-source cross-checks are described above. Because values passed through a chat assistant, every series was checked against the row counts and revenue totals the assistant reported, and against a second independent pull where one existed.

| Series | Rows | Check |
|---|---|---|
| NEAR daily, 2024 | 366 | Revenue sum $8,509,860.75 matches the source |
| NEAR daily, 2025 | 365 | Revenue sum $4,857,982.55 matches the source |
| NEAR daily, 2026 | 308 | Revenue sum $9,133,652.78 matches the source (two pulls agree) |
| Peers weekly | 740 (148 weeks x 5) | Per-asset revenue sums match to within cents; no missing weeks |
| NEAR total supply | 148 | Sum matches the source |
| NEAR buybacks | 196 | Sum matches the source |

Known gaps and choices:

- In 2024, transaction fees equal protocol revenue on every row. All 366 rows of the raw export `raw_near_daily_2024.csv` have identical `transaction_fees_usd` and `protocol_revenue_usd` values, and `near_daily.csv` takes its 2024 fees from that column (checked on 2026-11-12).
- Stablecoin supply is excluded. Two pulls of the same batch disagreed on it.
- Prices and market caps for 2026-09-07 to 2026-09-09 are blank in the source and left blank.
- The two most recent days (2026-11-03 and 2026-11-04) are provisional; the source revised one of them between pulls. They sit in the exploratory window only.
- Data-cleaning rules (single-day market-cap spikes, days where revenue equals fees after 2025-09-23, incomplete-day flags) were fixed in the pre-registration before any hypothesis test and are applied in `analysis_confirmatory.py`.

## Honesty notes

- Hypotheses were written before the confirmatory data was analysed, and all four are reported, including the ones that failed. This repository was created after the analysis, so its history cannot prove that order; the dated amendments in `PREREGISTRATION.md` are the record.
- Two exploratory claims I made early on (revenue in NEAR terms was flat; revenue growth was mostly price) were withdrawn when the revenue source turned out not to be NEAR-denominated. The withdrawal is dated in `PREREGISTRATION.md`.
- Analyses added after the tests are labelled post-hoc in `scenarios.py` and in the thesis.
- The public-source tests E1 to E5 are reported as they came out, including E3 (not supported) and E5 (inconsistent). Checks added afterwards are labelled exploratory in `extension_results.txt` and do not change any verdict.
- Limitations are listed in `THESIS.md`. The largest are a single regime, an Intents volume series whose definition DefiLlama does not document, and a break in Blockworks active addresses on 2026-04-02 that is probably a definition change (E4).

## Data terms

- **DefiLlama: raw data is not included.** DefiLlama's terms (https://defillama.com/terms) do not allow its data to be republished or mirrored without permission. The raw DefiLlama responses are therefore not in this repository or its git history (`PREREGISTRATION.md`, Amendment 8b). To re-pull, run `python run_all.py`, which fetches them from DefiLlama's free API into local files that git ignores, or run `python pull_defillama_intents.py` directly. The repository publishes only aggregates computed from them: window means, take rates, ratios and correlations.
- **Blockworks:** the Blockworks-derived CSV files (`near_*.csv`, `peers_weekly.csv` and the `raw_near_*` and `raw_peers_*` exports) are included only so the analysis can be reproduced. Whether Blockworks' terms allow this still needs checking.
- **BigQuery:** `raw_bigquery_daily_usage.csv` is a daily aggregate of NEAR's public BigQuery dataset and is subject to that dataset's terms.
